# design-sync NOTES

Source: `client/src/app/components/ui` (shadcn/ui-based), synced via the **package shape**, **synth-entry mode** (no real `dist/` build — the config's `pkg`/`srcDir` point at the app's own source folder; `PKG_DIR` resolves to `client/` via `--entry ./client/dist/index.es.js`, a path that deliberately doesn't exist so the converter falls back to scanning `src/app/components/ui/*.tsx`).

## Repo-specific setup

- **`cssEntry`** is `client/dist/assets/index-<hash>.css` — the app's real Vite build output, since the source stylesheet chain (`fonts.css` → `tailwind.css` → `theme.css` → `globals.css`) needs Tailwind v4's JIT compiler to resolve `@import 'tailwindcss'` into real utility classes. **This hash changes on every `npm run build`** — a re-sync must re-run `npm run build` in `client/` and update `cfg.cssEntry` to the new filename before rebuilding, or the bundle ships stale/missing styles.
- **Missing npm deps**: 19 of the 46 files import packages not in `client/package.json` (`@radix-ui/react-context-menu`, `react-hook-form`, `cmdk`, `embla-carousel-react`, `next-themes`, `vaul`, `input-otp`, `@radix-ui/react-{aspect-ratio,hover-card,menubar,navigation-menu,popover,progress,radio-group,slider,toggle,toggle-group}`, `react-day-picker`, `react-resizable-panels`) — these are real shadcn scaffold files never wired into the app's actual dependency list. Installed with `npm install --no-save <pkgs...>` into `client/node_modules` (package.json/lock untouched). **`react-resizable-panels` needed pinning to `@^2`** — latest (v4) renamed `PanelGroup`/`PanelResizeHandle` to `Group`/`Separator`, breaking `resizable.tsx`. **Re-sync gotcha**: `npm install --no-save` is NOT additive across separate invocations — each install call prunes any previously-added --no-save package not named in THAT command. Always install the full missing-deps list in ONE command.
- **`componentSrcMap`**: this DS has 46 files each exporting one "root" component (matching the file's own PascalCase name, e.g. `dialog.tsx` → `Dialog`) plus 2-20 flat subcomponent exports (e.g. `DialogTrigger`, `DialogContent`) with NO compound-namespace pattern (no `Dialog.Trigger = ...` static assignment) — so the converter's automatic subcomponent grouping (which depends on that pattern) never fires, and without the map all 238 exports would surface as flat top-level "components". `componentSrcMap` nulls out the ~192 non-root names so only the intended 46 get cards; the subcomponents remain fully importable (`import { DialogTrigger } from 'bigdata-community-client'`) for composition inside their parent's preview — componentSrcMap:null only removes the standalone card, not the runtime export.
- **`dtsPropsFor`**: hand-written for all 46 (no real `dist/.d.ts` tree exists, so ts-morph's extraction stubbed every Props interface to `[key: string]: unknown`). Written by reading each file's actual destructured props/JSX.ComponentProps<...> signature. If the real source component's prop shape changes, these will drift — re-check against source on future re-syncs, don't assume they're still accurate.

## Rendering conventions established this sync

- **Theming**: this app's real brand theme is dark-navy (`--background:#0a0f1f`, `--foreground:#eef2fb`, `--primary:` blue ~`#3b82f6`), not the plain-white shadcn defaults you'd guess from `globals.css`'s `:root` block — `theme.css` (loaded after `globals.css` in `index.css`'s import order, and with narrower/later-registered Tailwind `@layer` precedence) overrides those with the app's actual brand palette. **Every preview wraps its root in a themed stage** (`background: var(--background); color: var(--foreground); padding: 24px`) so components render in true context — a bare component on the raw white page canvas misrenders (e.g. the Button `ghost` variant's near-white text becomes invisible against white).
- **`asChild` + this repo's `<Button>` breaks Popper-anchored triggers.** `client/src/app/components/ui/button.tsx`'s `Button` is a plain function component, NOT wrapped in `React.forwardRef`. Any Radix `*Trigger asChild` that clones a `<Button>` child to inject a ref (DropdownMenu, Tooltip, and likely Popover/HoverCard/ContextMenu/Menubar-submenu the same way) silently fails to position/open the content — no error, just an empty portal. **Fix used throughout**: style the `*Trigger` directly with `className={buttonVariants({variant:...})}` instead of `asChild`+`<Button>`. Non-anchored overlays (Dialog/Sheet/AlertDialog/Drawer — fixed/centered/slide positioning, not a measured Popper anchor) are unaffected; `asChild`+`Button` works fine there. **This is a real app bug** (not a design-sync artifact) worth flagging to the repo owner separately — any real usage of `<Button>` as a Radix `asChild` trigger child anywhere in the actual app likely has the same silent-failure risk.
- **`ScrollArea` needs `type="always"`** in a static capture — Radix's default `type="hover"` scrollbar thumb never renders without a real pointer-hover event.
- **Overlay/portal components need `cfg.overrides.<Name>: {"cardMode":"single","viewport":"WxH"}`** to render at all in the capture: `Dialog`, `AlertDialog`, `Sheet`, `Drawer` all needed this (fixed/portal-positioned content escapes the per-cell cropped screenshot region otherwise). `Popover`, `HoverCard`, `ContextMenu`, `Tooltip` did NOT need it (their portal content stays within the stage's local bounds). `Toaster` was tried with the same override (`420x300`) and it did NOT fix it — see below.
- **Prefer a real default value over an empty state** on this dark theme — `InputOTP`'s empty slots were nearly invisible until given `defaultValue="482913"`; likely applies to any other component with a legitimately-empty default rendering (thin borders on `--input`/`--border` tokens read very low-contrast against the dark navy background).

## Known render warns (legitimate, not defects — don't re-flag on future syncs)

- **Badge** `secondary` variant: dark-on-dark, genuinely low-contrast against this theme. Real token, not a bug.
- **RadioGroup**/**Toggle** `outline`: unselected/unpressed border (`border-input` token) is low-contrast against the dark stage. Real token, not a bug.
- **Calendar**: renders English month/weekday headers — `react-day-picker` locale isn't wired through the shipped `Calendar` component (no `locale` prop passed). Cosmetic; a real source change, out of scope for design-sync.

## Toaster — shipped as floor card (unresolved)

`sonner`'s `Toaster` never shows a fired `toast()` in the headless capture, across 5 real attempts (effect-triggered call, pre-mount module-scope call, `duration: Infinity`, wrapping in a real `next-themes` `ThemeProvider forcedTheme="dark"`, and a `cfg.overrides` `cardMode:"single"` full-viewport capture to rule out per-cell cropping). The bundle/component itself is fully functional — a real app calling `toast()` is unaffected; this is purely a static-capture limitation (removed `.design-sync/previews/Toaster.tsx` so it ships the honest floor card instead of a silently-blank authored preview). **Re-sync risk / future ideas**: check if the capture harness's page-settle wait can be lengthened for this one component, or investigate whether sonner's portal-mount/store-subscription needs a real `document.visibilityState` or animation-frame tick that headless Chromium's default page state doesn't provide.

## Re-sync risks

- `cssEntry`'s filename hash changes every `client` build — must re-verify/update after `npm run build`.
- The 19 `--no-save` npm installs live only in `client/node_modules` (gitignored) — a fresh clone or CI checkout needs them reinstalled (single combined command, see above) before any rebuild.
- `dtsPropsFor` bodies are hand-maintained prose, not extracted — they will silently drift if the real component's props change and nobody updates this file.
- Toaster's floor-card status should be revisited if sonner or the capture harness's playwright version changes.
